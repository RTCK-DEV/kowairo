# 競合製品との動作比較

公開前の挙動検証。Kowairo は ASR→TTS カスケードのため、音声→音声直接変換の
競合とはアーキテクチャが異なる。ここでは「同一条件下でのユーザー観測挙動」を
比較し、差分をコードで詰めた記録。

## 比較対象

| 製品 | 方式 | 応答挙動 | 備考 |
|---|---|---|---|
| w-okada VCClient (RVC 系) | 音声→音声 直接変換 (chunk streaming) | 発話中から連続出力。実効遅延 ≈ バッファ+推論 ~0.5–1 s (GPU 前提) | 遅れが溜まると古いチャンクを破棄する bounded-lag |
| Voidol 3 (クリムゾンテクノロジー) | 音声→音声 直接変換 | 公称 ~20 ms 級。話しながら出続ける | 低遅延・低負荷を売りにする商用 |
| Seiren Voice | オフライン変換 | リアルタイム用途外 (比較対象外) | |
| Kowairo (旧) | VAD→ASR→文節分割→TTS | **発話終了まで無音** + ASR+TTS ~1–2 s | 長い発話ほど初音が遅い (max 15 s) |
| Kowairo (本版) | 同上 + 中間認識で先回り合成 | 発話中から安定文節を逐次出力 | 本 PR の変更点 |

## 計測方法

`scripts/bench_realtime.py` — 実際のパイプラインスレッドを `with_io=False`
で起動し、入力 WAV を 32 ms フレーム・実時間ペースで `feed_pcm` する
ヘッドレスベンチ。再生 drain も実時間で行われるためキュー滞留・破棄挙動も
実機と同じ。入力はエンジン自身が合成した 12.1 s の複文発話
（句読点を含む書き言葉 → ASR 入力として使用）。

指標:
- **respond** = 発話開始 → 最初の変換音声エンキュー (競合の「応答速度」相当)
- **e2e** = VAD 発話終端確定 → 最初の変換音声 (負なら終端前に音が出ている)

環境: Windows Server 2022 / CPU のみ / AivisSpeech Engine 1.2.0 (ONNX CPU) /
まお (style_id 888753760)。

## 結果 (12.1 s 入力、同一マシン)

| モード | respond | e2e | 備考 |
|---|---|---|---|
| interim OFF (旧挙動) | **14.0 s** | +2.2 s | 発話中は無音。終端 + ASR 0.2 s + TTS 2.0 s |
| interim ON (本版) | **5.1 s** | **−6.7 s** | 3.6 s / 4.7 s の中間認識で安定文節を先回り合成し、終端の 6.7 s 前から音が出ている |

参考: w-okada VCClient は発話中から ~0.5–1 s 周期で変換チャンクを出し続ける
(GPU 十分時)。Kowairo も「話しながら音が出続ける」挙動には達したが、
ASR→TTS カスケードの原理上、初音まで数秒かかる点は残る差分 (後述)。

## 同一条件下での挙動差と対策 (本 PR で実施)

| 観測差 | 原因 | 対策 |
|---|---|---|
| 発話中は完全無音 (~14 s) | VAD 終端まで ASR/TTS が始まらない | 中間認識ワーカー + 文節先回り合成 (`interim_asr`) |
| 初回変換だけ異常に遅い | エンジン/ASR の遅延ロード (~5.4 s 実測) | 起動時 warm-up (ASR 投げ捨て認識 + TTS「あ」合成) |
| 長い文節がまるごと無音化 | `drop_when_behind` 超過時に文節単位で丸ごと破棄 | サンプル粒度の先頭トリムに変更 + 上限を 900→3000 ms (1 文節分を収容) |
| 句読点なし認識で文節が巨大化 | ReazonSpeech が 、。を出さない入力がある (実測 45 字無分割) | 文節分割に長さ上限の強制分割を追加 |
| パススルー音のブロック境界歪み | 32 ms 毎の one-shot リサンプル | soxr ResampleStream で状態を継続 |
| 遅れ計測が不正確 | utterance 統計が発話終端基準のみ | 発話開始→初音の respond 指標を追加 (UI「応答」) |

## 残る構造的差分 (対応不可/見送り)

- **初音までの数秒**: 直接変換は ~数十〜数百 ms で出るが、ASR→TTS は
  「安定した認識前文節」が要るため原理上 4–6 s かかる。安定判定を緩めると
  誤認識の音声が先に出てしまうため、2 スナップショット一致を採用。
- **ASR が過去の認識を書き換える**: 中間認識は確定済みテキストが修正されると
  その発話の先回りを中断し、最終認識で全文を合成し直す (確定分は一度再生済み
  のため冒頭の数音が重複しうる。ライブ用途では「早く出す」を優先)。
- **音色の変換**: 競合は入力声色を変換するが、Kowairo は内容転写方式のため
  比較対象外 (仕様上の差異)。
- **CPU 負荷**: 中間認識は発話中 1 回/秒の追加 ASR 推論 (~0.2 s) — 競合の
  GPU 前提と違い CPU 完結のため増分は許容範囲と判断。

## 再現

```bash
python scripts/bench_realtime.py --input bench_in.wav --json out.json
python scripts/bench_realtime.py --input bench_in.wav --no-interim
```
